Learning Path

Beginner

Weeks 1–3 · foundations
  • Search operators — site:, filetype:, intitle:, and combining them (Google Custom Search, Google Advanced Search)
  • Reverse image search — comparing results across Google Lens, TinEye, and Yandex Images
  • Reading a WHOIS/DNS record — registrar, nameservers, creation date (who.is, ICANN Lookup)
  • Basic OPSEC — separating your research identity from your personal accounts

Intermediate

Weeks 4–8 · pivoting
  • Username correlation — cross-checking a handle with Sherlock, Namechk, and WhatsMyName
  • Email pivoting — holehe, h8mail, and Have I Been Pwned to trace an address's footprint
  • Metadata extraction — ExifTool, FotoForensics, and Jeffrey's Exif Viewer on images and documents
  • Archive diffing — comparing Wayback Machine and archive.today snapshots to spot edits

Advanced

Weeks 9+ · infrastructure & analysis
  • Infrastructure mapping — Censys, Shodan, and SecurityTrails to profile an organization's exposed assets
  • Threat correlation — IntelOwl and ThreatMiner to pull multiple analyzers into one report
  • Link analysis — Maltego or LinkScope to visualize relationships across a whole investigation
  • Counter-surveillance — Privacy Guides and PRISM Break to understand what you're exposing while you research

About OSINT

Open-source intelligence (OSINT) is the practice of collecting and analyzing information from publicly available sources — websites, social media, public records, and more — to answer a specific question. It's used by journalists, researchers, security teams, and investigators, and it depends entirely on using public information responsibly and verifying findings before acting on them.

How this site is built

OSINT Hub is currently a fully static site — one HTML file, no server, no database, no API keys. Every tool card links out to that service's own site, and the Research Launcher above just builds a URL for a public tool to open in your browser; nothing is looked up or stored here. That's intentional: any key placed in client-side JavaScript on a public GitHub Pages site is visible to anyone who views the page source, so authenticated APIs (like HIBP's paid breach-search API) are never wired in directly. Adding those later would mean a small separate backend that holds the API key and rate-limits requests on the site's behalf — the frontend would stay exactly as it is today.
